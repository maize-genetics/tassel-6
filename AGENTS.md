# AGENTS.md

Instructions for AI agents (and humans) working in this repository. Read this
file first in every session. It is short on purpose; details live in the linked
documents.

## What this project is

TASSEL 6 is the Kotlin Multiplatform successor to
[TASSEL 5](https://github.com/maize-genetics/tassel). One pure-Kotlin core is
compiled to the JVM, WebAssembly, and Native, and feeds a CLI, a shared
desktop/web UI (Compose Multiplatform), MCP agent tools, and native R/Python
bindings.

- Roadmap: [`docs/llm_notes/TASSEL_6_KMP_ROADMAP.md`](docs/llm_notes/TASSEL_6_KMP_ROADMAP.md)
- Decisions: [`docs/adr/`](docs/adr/README.md). Do not contradict an accepted
  ADR; propose a new one that supersedes it instead.
- Porting status: [`docs/porting-ledger.md`](docs/porting-ledger.md)
- Handoff format: [`docs/handoff/TEMPLATE.md`](docs/handoff/TEMPLATE.md)

## Repository layout

The repo is currently a single-module JVM skeleton. The target layout, landing
with the `kmp-skeleton` task, is:

| Path | Contents |
|------|----------|
| `tassel-core/` | Pure Kotlin model, I/O, and analyses. Targets jvm, wasmJs, macosArm64, linuxX64. |
| `tassel-cli/` | Clikt CLI generated from operation specs (JVM first, Native later). |
| `tassel-app/` | Compose Multiplatform UI: shared code plus `desktopMain` and `wasmJsMain`. |
| `testdata/` | Tutorial inputs and TASSEL 5 golden outputs (`testdata/golden/`). |
| `reference/` | Git-ignored shallow clone of TASSEL 5 source, read-only, for porting. |
| `docs/` | ADRs, porting ledger, handoffs, PoC notes. |

Later modules: `tassel-server/`, `legacy/tassel5-bridge/`, `bindings/{capi,r,python}/`.

## Hard constraints

1. **`commonMain` is pure Kotlin.** No `java.*`, `javax.*`, htsjdk, Guava, or
   any JVM-only dependency. Platform code goes in `jvmMain`/`wasmJsMain`/
   `nativeMain` behind `expect`/`actual` or an interface.
2. **No new dependencies** without saying so explicitly in the PR and, if the
   dependency is architectural, an ADR.
3. **Never edit files under `testdata/golden/`** unless the issue says so. These
   are the parity oracle; changing them to make a test pass is a failure, not a
   fix. Golden changes need the `golden-update` label and owner review.
4. **Do not change frozen contracts** (`GenotypeTable`, the operation DSL,
   `Engine`) without an ADR. If a contract blocks you, stop and say so.
5. **Stay inside the issue's scope.** Note related problems in the handoff; do
   not fix them in the same PR.
6. **Never commit to `main` or `develop` directly, and never merge PRs.** The
   maintainer merges.

## Branches, commits, versions

- Git flow: `main` (releases), `develop` (integration), `feature/<issue>-<slug>`,
  `release/<version>`, `hotfix/<slug>`. Feature PRs target `develop`.
- One task = one branch = one PR. Keep PRs reviewable (aim for under ~600 changed
  lines excluding test data).
- [Conventional Commits](https://www.conventionalcommits.org/): `feat(core): ...`,
  `fix(cli): ...`, `test(core): ...`, `docs(adr): ...`, `build: ...`, `ci: ...`.
  Scopes: `core`, `cli`, `app`, `server`, `bridge`, `bindings`, `testdata`,
  `docs`, `adr`, `build`, `ci`.
- SemVer pre-releases: `6.0.0-poc.1`, `6.0.0-alpha.N`; nightlies
  `6.0.0-dev.YYYYMMDD`. Changelog generated by git-cliff.

## Session protocol

At the start of a session:

1. Read this file, the issue, the roadmap section it cites, the ADRs it cites,
   and the most recent handoff (the last merged PR body for that area, or
   `docs/handoff/` for multi-session work).
2. Branch from an up-to-date `develop`.
3. If TASSEL 5 source is needed, read it from `reference/tassel5/` (fetched by
   `scripts/fetch-reference.sh` once that exists), or from
   <https://github.com/maize-genetics/tassel> at the pinned tag in ADR-0009.

At the end of a session:

1. Run the verification commands and paste real output into the PR.
2. Update `docs/porting-ledger.md` if you ported, bridged, or retired anything.
3. Write the handoff in the PR body using `docs/handoff/TEMPLATE.md`.
4. Open the PR against `develop`. Do not merge it.

## Stop and ask (do not improvise) when

- A golden test fails and the cause is not an obvious bug in your port.
- Matching TASSEL 5 would require a JVM-only dependency in `commonMain`.
- A frozen contract or accepted ADR is in the way.
- The issue is ambiguous about behavior a user would notice (output format,
  defaults, rounding, ordering).

## Porting conventions

- Port behavior, not structure. Kotlin idioms over Java patterns (no builders
  where a data class with defaults works, no plugin base-class inheritance).
- Keep TASSEL 5 semantics exactly: default values, missing-data handling,
  tie-breaking, output ordering, and number formatting. Cite the source class
  in a KDoc `@see` on the ported entry point.
- Record TASSEL 5 parameter names as `legacy = "..."` on operation spec
  parameters so the CLI translator and rTASSEL compatibility keep working.
- Analyses consume genotypes through the site-block API, never by
  materializing a full taxa x sites matrix unless the algorithm requires it.
- Numeric code: `Double` throughout; avoid platform-dependent math
  (`kotlin.math` only); PCA eigenvectors are compared up to sign.

## Verification

Commands become available as the `kmp-skeleton` task lands:

```bash
./gradlew :tassel-core:allTests        # jvm, wasmJs (Node), native tests
./gradlew :tassel-core:jvmTest         # fast inner loop
./gradlew check                        # everything CI runs
./gradlew :tassel-cli:run --args="--help"
./gradlew :tassel-app:run              # desktop
./gradlew :tassel-app:wasmJsBrowserDevelopmentRun   # web
```

A task is done when its issue's "Done when" list is satisfied on every listed
target, `./gradlew check` passes, and the PR contains the handoff.
