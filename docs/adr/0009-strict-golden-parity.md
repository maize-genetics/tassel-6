# ADR-0009: Strict numerical parity through TASSEL 5 golden tests

- Status: Accepted (pinned version to be confirmed in the `golden-data` task)
- Date: 2026-10-29

## Context

TASSEL is used in published research. Users must be able to trust that a
TASSEL 6 analysis gives the same answer as TASSEL 5. Most porting will be done
by AI agents, which need an objective, automatic check of correctness.

## Decision

- Ported analyses must match outputs from a pinned TASSEL 5 release on the
  tutorial datasets (`mdp_genotype.hmp.txt`, `mdp_genotype_w_depth.vcf`) and on
  selected synthetic data.
- Golden outputs are generated by a script, stored in `testdata/golden/` with a
  `MANIFEST` recording the TASSEL 5 version, the exact commands, and the
  tolerance per analysis.
- Tolerances: exact for counts, filters, and text; `8e-6` absolute for kinship
  (matching TASSEL 5's `CenteredIBSTest`); PCA eigenvalues by tolerance and
  eigenvectors up to sign.
- Golden files are protected: changing them requires the `golden-update`
  label and code-owner review.

## Pinned version

The plan named TASSEL 5.3.0. The TASSEL 5 repo currently reports version 5.3.0
but its latest release tag is `v5.2.98`. The `golden-data` task must either tag
5.3.0 in TASSEL 5 or pin `v5.2.98`, and record the choice in the manifest.

## Consequences

- Golden tests are the definition of done for every port.
- Intentional deviations from TASSEL 5 (bug fixes) need an ADR and a separate
  golden set, so parity and fixes are not confused.
- Floating-point summation order must be kept close to TASSEL 5's to stay
  within tolerance.

## Alternatives considered

- Statistical agreement (for example, correlation > 0.999): too weak to catch
  off-by-one and missing-data bugs.
- Hand-written expected values only: do not scale to many analyses.
