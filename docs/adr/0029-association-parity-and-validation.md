# ADR-0029: Parity and validation policy for association mapping

- Status: Accepted
- Date: 2026-11-25

## Context

ADR-0009 makes TASSEL 5 `v5.2.98` goldens the definition of done for ports. ADR-0020 showed how a
modernized kernel can keep that guarantee with a documented tolerance and a retained TASSEL 5-order
reference path. Association mapping strains both rules:

- GLM and MLM statistics come out of long chains of floating-point work (sweeps, inverses, an
  iterative REML search), so bit-exact parity with a decomposition-based port (ADR-0025) is
  neither realistic nor desirable.
- Some TASSEL 5 behaviors are wrong or fragile (p-values that underflow to 0, inversion of
  ill-conditioned matrices, thread-dependent ordering), and the planning brief asks that departures
  be intentional, documented, and independently validated rather than silently copied or silently
  fixed.
- A TASSEL 5 golden only says "same as TASSEL 5". It cannot say "correct", and it cannot cover
  behavior TASSEL 5 lacks (log p, additive-only tests, per-marker REML, effect alleles).

## Decision

### Three kinds of reference

1. **TASSEL 5 goldens** (`testdata/golden/glm-*`, `testdata/golden/mlm-*`), generated by
   `scripts/generate-goldens.sh` from the pinned standalone on the tutorial data and on small
   synthetic sets, through the TASSEL 5 command line. They are the oracle for every output TASSEL 5
   produces, through the TASSEL 5-compatible report writers (ADR-0027). The usual rules apply:
   never edited by hand, `golden-update` label, owner review.
2. **Independent oracle fixtures** (`testdata/oracle/`), a new tree with the same never-edit rule
   as `testdata/htslib/` (ADR-0022) and no `golden-update` label. Scripts under `scripts/oracle/`
   regenerate them with pinned tools, recorded in `testdata/oracle/MANIFEST`:
   - R `lm()`, `anova()`, `drop1()`, and `aov()` error strata for designs, contrasts, sums of
     squares, and nested error terms; an independent base-R REML profile over `delta` and a pinned
     package fit for variance components;
   - NIST StRD linear-regression datasets (Longley, Wampler1–5, Filip) with certified values, for
     the QR and OLS kernels;
   - `mpmath` (arbitrary precision) for log-space tail probabilities;
   - PLINK 2 `--glm` for additive dosage tests and GCTA `--mlma` (null-model variance reuse) and
     GEMMA `-lmm` (per-marker REML) for mixed models, run in pinned containers, only where model
     definitions, allele coding, and missing-data handling are made equivalent first. Each fixture
     records the exact command and the equivalence argument.

   TASSEL 5's own expected outputs in the pinned test-data tarball (`ExpectedResults/
   discreteSitesFELM.txt`, `MLM_statistics_nocomp_nop3d.txt`, `phenotypeLMreport.txt`, and the
   R-computed BLUEs hard-coded in `PhenotypeLMTest`) are cross-checks of this kind when their
   inputs are available.
3. **Hand-computed and property tests** in `commonTest`: tiny designs solved by hand, invariance
   (row order, taxa order, trait order), FWL equivalence against a full refit, simulated known
   effects, and null simulations.

### Tolerances

Tolerances are declared per file and per column in the relevant MANIFEST, never in test code:

- **Exact:** marker names, positions, trait names, row order, counts (observations, taxa, classes),
  and degrees of freedom.
- **Statistics (F, t, SS, MS, R², estimates, SE):** relative tolerance, set per golden by the
  issue that adds it, starting from `rel 1e-8` for GLM and `rel 1e-6` for MLM P3D, and tightened
  if the port does better. A port that cannot meet the stated tolerance stops and asks (AGENTS.md).
- **p-values:** compared as `log10 p` with an absolute tolerance (starting `abs 1e-6`) once
  `p < 1e-300` or TASSEL 5 prints `0.0`; relative otherwise. A TASSEL 5 `0.0` is checked only as
  "TASSEL 6 `log10 p` is below the underflow bound".
- **Variance components and heritability:** relative tolerance against TASSEL 5's EMMA estimate,
  plus an objective check: evaluated with the same REML likelihood function, TASSEL 6's optimum
  scores at least as well as TASSEL 5's (to `abs 1e-8`); TASSEL 5's printed likelihood carries
  constants of its own and is compared only in the compatible report. A better optimum is allowed
  only through the departure procedure below.

### Intentional departures

A behavior that knowingly differs from TASSEL 5 (for example, finite `log10 p` where TASSEL 5
prints `0`, a rank-deficient marker reported as not estimable rather than as NaN, or a different
REML optimum on a flat likelihood) needs:

1. a row in the epic's departure table naming the TASSEL 5 behavior, the TASSEL 6 behavior, and why;
2. an independent oracle fixture (kind 2) or hand-computed test showing TASSEL 6 is right;
3. no change to the TASSEL 5 golden; the golden comparison excludes only the departing cells, by an
   explicit, reviewed rule in the MANIFEST, not by loosening a tolerance.

Departures that change user-visible defaults (output columns, default encoding, default missing
handling) also need maintainer approval in the issue before implementation.

### Cross-platform parity

The same `commonTest` suites run on jvm, wasmJs (Node), and linuxX64. Results across targets must
agree with each other within the tolerances above; any platform kernel (BLAS, GPU) must agree with
the pure-Kotlin reference path within tolerances declared by the issue that adds it.

## Consequences

- Each GLM and MLM issue knows exactly what "done" means before it starts.
- `testdata/oracle/` adds a maintained fixture tree and pinned external tools, run only by people
  regenerating fixtures, never by CI.
- Some TASSEL 5 outputs will be matched only to documented tolerances, as kinship already is.

## Alternatives considered

- **Bit-exact TASSEL 5 parity.** Forces the sweep and explicit inverses into the core. Rejected.
- **Statistical agreement only (correlation of p-values).** ADR-0009 already rejected it as too weak.
- **External tools as the only oracle.** They answer slightly different questions (allele coding,
  imputation, df conventions), so agreement needs a careful equivalence for each. Rejected as the
  primary oracle, kept as kind 2.
