# Association mapping epic: issue drafts

Drafts for the GitHub epic and its sub-issues, in the `agent-task` template's shape and epic #155's
conventions. Plan and rationale: [`ASSOCIATION_PLAN.md`](ASSOCIATION_PLAN.md). Once the issues
exist on GitHub they are the source of truth and this file can be deleted.

Conventions for every issue below:

- Label `agent-task`; add `golden-update` when the issue adds files under `testdata/golden/`, and
  `needs-decision` plus `adr` for decision issues. Parent: the epic.
- `T5` = `reference/tassel5/src/main/java/net/maizegenetics` (pinned `v5.2.98`, ADR-0009).
  `T6` = `tassel-core/src/commonMain/kotlin/net/maizegenetics/tassel`.
- Every "Done when" also includes, and the drafts do not repeat:
  - `./gradlew check` passes;
  - no new dependencies; no `java.*` in `commonMain`;
  - porting ledger rows added or updated;
  - the handoff (`docs/handoff/TEMPLATE.md`) is in the PR body.
- Specs are declared with their kernels and registered in `TasselOperations` only in D1, so no
  front end lists an operation it cannot feed (#155's rule).
- Golden-adding issues (B1, B6, C1, C5) merge one at a time; each rebuilds the MANIFEST, and existing
  golden files must come out byte-identical.
- Standard verification block, unless an issue says otherwise:

  ```bash
  ./gradlew :tassel-core:allTests
  ./gradlew check
  ```

## Epic

**Title:** Association mapping: GLM and MLM on a shared statistical modeling layer

**Labels:** `epic`

**Body:**

TASSEL 6 has phenotypes, joins, genotype-phenotype alignment, kinship, PCA, and the F, t, and
chi-square distributions (epic #155), but no association mapping. This epic adds GLM and MLM with
TASSEL 5 parity where it matters, on a reusable statistical modeling layer that later methods
(logistic, stepwise, LOCO, FarmCPU/BLINK, genomic prediction) can build on.

Roadmap Phase 2, `docs/llm_notes/TASSEL_6_KMP_ROADMAP.md`: "GLM, MLM (EMMA/P3D with compression),
… Manhattan and QQ plots". The full audit, inventory, and plan are in
`docs/llm_notes/ASSOCIATION_PLAN.md`.

### Decisions to approve first (A1)

- ADR-0025: decomposition-based modeling layer (pivoted QR, Cholesky, eigen; no explicit inverse;
  FWL reuse; log-space p-values).
- ADR-0026: `DataSet` inputs, taxon alignment, missing data without silent imputation,
  replicates, kinship input, marker encodings behind `MarkerSource`.
- ADR-0027: columnar `AssociationTable`, `AssociationSink`, TASSEL 5-compatible and modern reports,
  provenance.
- ADR-0028: REML (EMMA-style search), P3D default, per-marker re-estimation, kinship scaling and
  heritability, failure semantics.
- ADR-0029: TASSEL 5 goldens plus `testdata/oracle/` independent references, per-column
  tolerances, departure procedure.

### Shape of the work

(Mermaid graph from `ASSOCIATION_PLAN.md` section 7.)

- **First batch:** A1 (decisions); then A2, A6, B1, C1, and E1 in parallel; then A3, A4, B2, and B3.
- **Priority:** correctness and parity of GLM, then MLM P3D, then speed, then front ends.
- **Goldens:** B1, B6, C1, and C5 each extend `scripts/generate-goldens.sh`; merge them one at a time.

### Out of scope

Compressed MLM beyond C5, weighted MLM, LOCO, logistic regression, stepwise, FarmCPU/BLINK,
multivariate and GxE models, GPU kernels, Arrow/Parquet output, the TASSEL 5 pipeline translator.
They inform the design and get their own epics.

### A4 `feat(core)`: dense linear algebra kernels

**Labels:** `agent-task`

**Goal.** `T6/math` has a column-major `DenseMatrix`, pivoted Householder QR with rank detection,
Cholesky, triangular solves, and level-1/2/3 kernels behind a replaceable internal hook, validated
against NIST StRD certified values.

**Roadmap section.** Phase 2 teaching MVP. Epic (association).

**TASSEL 5 sources.**
- `matrixalgebra/Matrix/DoubleMatrix.java`, `DoubleMatrixFactory.java`, `ColtDoubleMatrix.java`
  (the operations association code calls; for coverage, not structure)
- `matrixalgebra/decomposition/QRDecomposition.java`, `SymmetricEigenvalueDecomposition.java`
- `stats/linearmodels/SolveByOrthogonalizing.java` (TASSEL 5's own orthogonalization path)

**Contracts and ADRs to build on.** ADR-0025, ADR-0020 (results independent of worker count; the
`kinshipTriangleUpdate` hook pattern), `SymmetricEigenDecomposition` (unchanged).

**What to build.**
- `DenseMatrix(rows, columns, data: DoubleArray)` (column-major), column views, workspace reuse.
- `HouseholderQr.of(matrix, pivot = true)`: rank with tolerance `max(m, n) * eps * |r11|`,
  permutation, `applyQt(b)`, `applyQ(b)`, `solve(b)` (least squares; minimum-norm not required),
  `rDiagonal`, and `rInverseRowNorms` for standard errors without forming an inverse.
- `Cholesky.of(matrix)` returning success or the failing pivot index; `solve`.
- Triangular solves; `dot`, `axpy`, `gemv`, `gemm`, `syrk` behind
  `internal fun interface DenseKernels` with a pure-Kotlin default.
- A `suspend` overload of `SymmetricEigenDecomposition.of` that reports progress (C2 needs it);
  results identical to the non-suspending version.

**Done when**
- [ ] NIST StRD coefficients and SEs match certified values to at least 9 significant digits (Longley to 12); Filip either reaches 7 digits or reports rank deficiency, never a wrong full-rank answer
- [ ] Rank detection tests: exact collinearity, near collinearity at the tolerance, zero columns, `n < p`
- [ ] Results identical with one and several workers
- [ ] Tests pass on jvmTest, wasmJsNodeTest, linuxX64Test (CI)

**Out of scope.** Model terms (A5). BLAS, FFM, GPU backends. SVD.

**Verification commands.** Standard.

**Where should this run.** Cloud agent or worktree (headless, parallel-safe).

**Depends on.** A2.

### B2 `feat(core)`: marker encodings and the `MarkerSource` seam

**Labels:** `agent-task`

**Roadmap section.** Phase 2 teaching MVP, "GLM". Epic (association).

- Existing test: `src/test/java/net/maizegenetics/analysis/association/DiscreteSitesTest.java`

**Contracts and ADRs to build on.** ADR-0026, ADR-0012 (`siteBlocks(taxa = …)`, frozen),

**What to build.**
- `MarkerSource` (internal interface) and `GenotypeMarkerSource`.
- Encodings `genotype`, `additive`, `additive-dominance`, `dosage`; effect allele rule from
  ADR-0026 and decision Q2; multiallelic handling per ADR-0026.
- TASSEL 5's class order, reproduced per analysis: GLM sorts IUPAC genotype strings with the ACGT
  homozygotes first, then everything else alphabetically (`LM/ModelEffectUtils.getIntegerLevelsSortedByGenotype`);
  MLM puts homozygotes first by byte, then heterozygotes (`ModelEffectUtils` l.159–179). The last

- TASSEL 5's `add_F` inputs: one dosage column per allele except the last, alleles in frequency

- `dosage` from `analysis.ReferenceProbability`, with NaN dosages treated as missing (TASSEL 5's MLM
  NaN check never fires; a recorded departure).
- Labels: TASSEL 5 IUPAC genotype strings and explicit allele strings.
- Reads one site block at a time; nothing allocates per observation per marker beyond reusable
  buffers.

**Done when**

**Labels:** `agent-task`

**Goal.** `association.glm` fits TASSEL 5's GLM for every trait and marker of a `DataSet` and

**Roadmap section.** Phase 2 teaching MVP, "GLM". Epic (association).

**What to build.**

### C5 `feat(core)`: compressed MLM

**Labels:** `agent-task`, `golden-update`

**Goal.** `mlm` supports TASSEL 5's compression (`Optimum` and custom levels): clustering taxa on
