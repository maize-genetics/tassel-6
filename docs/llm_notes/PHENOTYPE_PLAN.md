# Phenotype data support: inventory and phased plan

Epic [#155](https://github.com/maize-genetics/tassel-6/issues/155). Written 2026-11-22 at the start of the epic; the issues are the live task list, and ADR-0023 and ADR-0024 hold the decisions.

## Context

Roadmap Phase 2 (`docs/llm_notes/TASSEL_6_KMP_ROADMAP.md:269`) opens with "Phenotypes (`<Phenotype>`, `<Trait>`, `<Covariate>`), intersect and union joins, and F, t, and chi-square distributions." GLM, MLM, and LD all depend on it. TASSEL 6 today has only a write-only `table.PhenotypeTable`, used for PCA output. There is no phenotype reader, join, filter, transform, summary, or special function in the codebase.

**Decisions made with the maintainer when the epic was planned:**
- **Clean redesign.** TASSEL 5 is the reference for the *file formats* only:
  - TASSEL 5 files load with the same values.
  - TASSEL 6 output loads in TASSEL 5.
  - Join, missing-value, and filter semantics are defined fresh in ADRs.
  - ADR-0009 parity applies to format values, transform numerics on valid inputs, and distributions. Join results get hand-written expected outputs.
- **Float storage, Double math.** Numeric attributes are `FloatArray`, with NaN as the only missing marker. Analyses read them as `Double`. This matches the TASSEL 5 values bit for bit and the existing PCA output.
- **Additive multi-input.** A core wrapper input type (working name `DataSet`) keeps join operations single-input. `Engine`, `RunRequest`, and the DSL do not change. Recorded in an ADR.
- **Delivery.** One `agent-task` issue per task under epic #155. New goldens go under `testdata/golden/phenotype-*/` and `testdata/golden/stats/`, generated by the extended `scripts/generate-goldens.sh`. Existing golden files must come out byte-identical.

**Oracle inputs** (pinned `tassel_test_data_v1` tarball, cached at `build/goldens/dataFiles`):
- `Tutorial/mdp_traits.txt`, `Tutorial/mdp_population_structure.txt`
- `PhenotypeTests/{basic_phenotype_test,version4format_test,version4format_covariate}.txt`
- `CandidateTests/{earht_with_rep,mdp_traits_nomissing}.txt`

The pinned TASSEL 5 standalone bundles `colt-1.2.0.jar` and `commons-math3-3.4.1.jar`, so distribution goldens come from the exact libraries TASSEL 5 runs.

**Architectural concerns:**
1. Single-input operations. Handled by ADR-0024 and the `DataSet` wrapper.
2. Front ends must not list phenotype operations before they can feed them. Specs are declared in core with their tasks, and registry entries are added in E1.
3. `String.toFloat()` is not `Float.parseFloat` off the JVM (double rounding, `f` suffix). A1 adds a parser that matches it.
4. The app's `Dataset` is genotype-only. E2 generalizes it.
5. Distributions are dependency-free ports of Cephes (via Colt, CERN license: keep the notice in KDoc). No new dependencies anywhere in this epic.

## Phased tasks (one issue → one branch → one PR each)

All tasks are `tassel-core` `commonMain` unless noted. Every task's "Done when" includes:
- `./gradlew check` passes;
- no new dependencies and no `java.*` in `commonMain`;
- the ledger row is updated;
- the handoff is in the PR body.

Tasks that add goldens get the `golden-update` label.

### Phase A — Representation and formats (priority)
- **A1 (#156) `feat(core)`: typed phenotype model, ADR-0023, and the `<Phenotype>` reader.** See #156 and ADR-0023.
- **A2 (#157) `feat(core)`: legacy readers** for `<Trait>`, `<Covariate>`, `<Factor>`, and `<Header name=x>`, plus format detection in `PhenotypeFiles.read`.
  - `<Header>` reshapes to long format: one row per (line, level), with a factor column per header. Traits and levels keep first-appearance order. Absent cells are missing.
  - Goldens come from TASSEL 5 `-t <file> -export … -exportType Phenotype` for `mdp_traits`, `mdp_population_structure`, `version4format_test`, `version4format_covariate`, and `mdp_traits_nomissing`. They are compared with the new `phenotype rows-unordered` tolerance (values and types; taxa-column name and row order free).
  - Depends on A1.

### Phase B — Single-table operations
- **B1 (#158) `feat(core)`: immutable phenotype filters and the `filter-phenotype` spec.**
  - Keep or drop rows by taxa list, factor levels, a numeric range on an attribute, or missing values in chosen attributes.
  - Keep or drop attributes by name or type; retype data↔covariate.
  - `legacyPlugin = "FilterTraitsPlugin"`, with `excludeLastTrait` mapped as `legacy`.
  - Hand-written expected tables. Depends on A1.
- **B2 (#159) `feat(core)`: phenotype summary and missingness.** A `PhenotypeSummary` wrapper result (the `GenotypeSummary` pattern) with three `ResultTable`s:
  - attributes: type, n, missing, fraction missing, mean, SD (n−1), min, max;
  - factor levels and their counts;
  - taxa: observations and missing cells.

  New behavior, so there is no T5 golden; tests use hand-computed values. Depends on A1.
- **B3 (#160) `feat(core)`: trait transforms and the `transform-phenotype` spec** (`legacyPlugin = "TransformDataPlugin"`, legacy names `traits`, `factor`, `log`, `power`, `standardize`).
  - Math is done in Double, then narrowed to Float.
  - Standardize optionally within factor-level groups.
  - New NaN or ±Inf results become missing, with a warning count.
  - Goldens: T5 `-TransformDataPlugin` on `mdp_traits` (log natural/base_10, power 0.5, standardize) and on `earht_with_rep` (standardize by `rep`), at `rel 1e-6`.
  - Depends on A1.

### Phase C — Joins
- **C1 (#161) `docs(adr)`: ADR-0024, the multi-input `DataSet` and join semantics** (`needs-decision`, `adr`). It proposes:
  - **Keys:** taxon plus every shared factor (exact name). A missing key matches nothing.
  - **Intersect** is a true inner join; **union** is a full outer join.
  - **Order:** left rows in their order, each followed by its matched right rows in right order. Union appends unmatched right rows in right order.
  - **Columns:** left columns, then the right side's new columns.
  - **`multiple`:** what to do with many-to-many key matches (`error` by default, or `cartesian`). One-to-many matches, such as replicates against a Q matrix, are allowed.
  - **`collision`:** what to do with shared non-key names (`error` by default, `suffix`, or `coalesce`). Type mismatches are errors unless `suffix` is chosen.
  - **N-way joins** are a left fold.
  - **Genotype alignment:** phenotype rows drive the result. Intersect keeps rows with genotypes. Union also appends an all-missing row for each genotype-only taxon.
- **C2 (#162) `feat(core)`: `DataSet` plus phenotype joins** (`joinPhenotypes`, and a `join-phenotypes` spec with `type`, `multiple`, and `collision` parameters; legacy `IntersectionAlignmentPlugin`/`UnionAlignmentPlugin`).
  - Hand-written fixtures in `testdata/phenotype/` cover replicates, environment factors, many-to-many, every collision mode, missing keys, ordering, and 3-way joins.
  - Cross-check goldens: T5 `-t mdp_traits -q mdp_population_structure -intersect/-union`, compared `phenotype rows-unordered`.
  - Depends on A1 and C1.
- **C3 (#163) `feat(core)`: genotype–phenotype alignment.** A `GenotypePhenotype(genotypes, phenotype, genotypeRow: IntArray)` that uses `GenotypeTable.taxa` and `siteBlocks(taxa = …)`, never copying genotypes, plus a `join-genotype-phenotype` spec over a `DataSet`. Depends on C2.

### Phase D — Statistical foundations (independent; can run in parallel with A–C)
- **D1 (#164) `feat(core)`: special functions in `T6/stats/`.** Port Colt/Cephes `gamma`, `logGamma`, `incompleteBeta` (power series and both continued fractions), `incompleteGamma`, and `incompleteGammaComplement`, plus `fTestPValue(F, df1, df2)` with `LinearModelUtils.Ftest` semantics.
  - Golden `golden/stats/special-functions.txt` comes from a new `scripts/golden/Distributions.java` harness compiled against the standalone's Colt jar, full-precision `Double.toString`, `rel 1e-13`.
- **D2 (#165) `feat(core)`: distributions API.** `FDistribution`, `StudentTDistribution`, and `ChiSquaredDistribution`, each with `pdf`, `cdf`, `sf` (upper tail computed directly, never `1 - cdf`), `quantile`, and `inverseSf`.
  - `require` checks on df (finite, > 0) and on p ∈ [0, 1].
  - Quantiles use a safeguarded Newton/bisection solver.
  - Goldens from the same harness:
    - Colt `Probability.studentT`, `chiSquareComplemented`, and the F tails at `rel 1e-12`, including tails down to 1e-300;
    - commons-math quantiles at `abs 1e-9`.
  - Round-trip identity tests. Depends on D1.

### Phase E — Integration (after B1 and C2)
- **E1 (#166) `feat(cli)`:**
  - Phenotype `--input`, chosen by content sniffing for `<Phenotype`/`<Trait`/`<Covariate`/`<Header`.
  - A repeatable `--input` for `DataSet` operations.
  - Register the phenotype specs in `TasselOperations`.
  - Output through the existing `is PhenotypeTable` branch.
- **E2 (#167) `feat(app)`:**
  - Generalize `Dataset` to genotype and phenotype datasets.
  - Open phenotype files on desktop and web, and bundle the tutorial traits.
  - Filter the Analyze buttons by input type.
  - Export `<Phenotype>`.
  - Include screenshots.

**Future consumers (out of scope):** GLM (`FixedEffectLMPlugin`), MLM, LD (`FisherExact`), BoxCox, imputation, average/subtract by taxa, PLINK phenotype export.

Dependencies: A1 → {A2, B1, B2, B3, C2}; C1 → C2 → C3; D1 → D2; {B1, C2} → E1 → E2.
